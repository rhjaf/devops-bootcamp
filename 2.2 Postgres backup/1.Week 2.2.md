## Performing daily backup from a postgres table and send it to a remote server
In this setup we will adjust a daily backup for a postgres table on Ubuntu 22.04 jammy. It is required to do the backup tasks via shellscripting

1. First of all if you can not connect to the postgres as postgres default user (`psql -U postgre`) and encounter some erors like `Peer authentication failed for user postgres` you need to do the following. First you need to change the default password for `postgres` user (if you can not do this jump to the next step)  
    ```bash
    sudo -i -u postgres psql
    ALTER USER postgres PASSWORD 'mynewpassword';
    ```

    Next add the following lines to `/etc/postgresql/14/main/pg_ident.conf` to map Our ubuntu `root` and `ubuntu` user to postgres `postgres` user
    ```bash
    # MAPNAME       SYSTEM-USERNAME         PG-USERNAME
    user1           root                    postgres
    user2           ubuntu                  postgres
    ```
    Next add the following lines to `/etc/postgresql/14/main/pg_hba.conf` to be able to login to postgres database as default `postgres` user for `root` and `ubuntu`
    ```bash
    #TYPE  DATABASE        USER            ADDRESS                 METHOD
    local   all             postgres                                peer map=user1
    local   all             postgres                                peer map=user2
    ```
    Now we can connect to postgres as `postgres` when we logged in as `root` or `ubuntu` in our linux by running `psql -U "postgres"` and also we are able to execute postgres related commands `pg_dump -U postgres -d database -f dump.sql`.

    There is another way in case you don't want to edit the two below files: First we edit the file `/etc/postgresql/14/main/postgresql.conf` by setting the `listen_addresses = '*'`. After that we need to set `-h` option all psql commands (e.g `psql -h 127.0.0.1 -U user -d database`,`pg_dump -h 127.0.0.1 -U postgres`,... ) 

    After all these changes restart postgres 
    ```bash
    sudo /etc/init.d/postgresql restart
    ```
2. The below scripts creates backups from `test` table and send it to a remove server as archive (The remote server should have install `rsync` on)
    ```bash
    BACKUP_DIR=~/postgres_backup
    DATE=$(date +%Y-%m-%d_%H-%M-%S)
    BACKUP_FILE="${BACKUP_DIR}/${DATE}.sql.gz"
    echo "$BACKUP_FILE"
    pg_dump -U postgres -d test -t test | gzip  > "$BACKUP_FILE"
    echo "${BACKUP_DIR}"
    rsync -avz "$BACKUP_FILE"  arch@192.168.33.129:/home/arch/psb
    find "$BACKUP_DIR" -name "*.sql.gz" -mtime +7 -delete
    ```
3. Now we add the following line to `crontab` by entering command `crontab -e` to executing the above shellscript everyday at 1AM.
    ```bash
    0 1 * * * ~/backup >> ~/postgres_backup.log 2>&1
    ```
    Next restart the cron service
    ```bash
    systemctl restart cron.service
    ```
